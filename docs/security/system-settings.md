# System settings and policy rules: security notes

Code: `internal/sysconfig`, `internal/config` (provenance, overlay), `internal/store/sysconfig.go` (migration 0009), `internal/web/sysconfig.go`, `internal/web/policyrules.go`, `internal/app/sysconfig.go`, `internal/mqttbus/probe.go`.

Lesson from TasmoAdmin: it wrote all of `$_POST` into its config file. Here a web session can never change how users sign in, which ports are open or where keys live.

| S1  | Three kinds of keys. Bootstrap and security settings (TRUSTED_PROXIES, PUBLIC_URL, BASE_PATH, LISTEN, TLS_*, FIRMWARE_LISTEN, DATA_DIR, LOCAL_LOGIN, keys, INITIAL_ADMIN_PASSWORD, header mode) are not in `sysconfig.Fields`: environment only, listed read-only (secrets `***`, URL user info dropped). The sign-in settings (`ui:"lock"`: AUTH_MODE `local`\|`oidc`, OIDC_*, groups) are editable and environment-lockable, as are LOG_LEVEL and the secret METRICS_TOKEN (write-only, live, a value from the environment wins and is never copied into the database). ## Live or restart

Live (no restart): device networks (shared network set), the MQTT broker (a `mqttbus.Switch` moves the subscribers of health, discovery, updates and the console to the new connection; a disabled bus puts devices back on HTTP polling), backup retention and schedule, update parallelism / OtaUrl restore / relay state age, poll interval and telemetry period, the policy live-read interval, the scheduled scan, MQTT discovery, metric labels, audit retention and the policy rules. Restart required: the firmware group (`FIRMWARE_BASE_URL`, sources, single-source, refresh interval: the firmware cache, the device-facing listener and the OTA routes are built at start) and the sign-in settings; the page shows "restart required" until the running process holds the stored value. The scheduled scan obeys the networks in force now.

## Residual risk (accepted)

- Header mode: a hijacked browser behind the proxy can still change the routine settings (networks, MQTT, intervals, discovery, policy rules); there is no step-up for them by design (proportionate homelab security). Put a re-authentication policy on `/settings/system*` and `/policy/rules*` at the proxy if that matters.
- The broker host is chosen by the admin and may be outside DEVICE_NETWORKS (a broker legitimately lives elsewhere); only the always-blocked ranges are refused. A malicious admin can still make the server open a TCP/TLS connection to any other reachable host (accepted, S18).
- A wrongly saved sign-in setting is applied after the next restart; local accounts (the login page and the host CLI) keep working, and a stored OIDC client secret that cannot be decrypted makes the server fall back to local sign-in.

## Residual risks (review 2026-10-19)

Low/Info findings, accepted under the proportionate-security principle:

- Test SSO lets an admin probe the LAN coarsely (the always-blocked ranges stay blocked, errors are coarse); go-oidc error snippets appear only in the logs.
- The OIDC client secret is bound to the issuer `host:port` only. Another path on the same host could serve a different `token_endpoint`; exploiting it needs an admin with step-up.
- `LOCAL_LOGIN=false` via the environment plus the UI switch to `oidc` removes the break-glass login. Recover with the environment `AUTH_MODE=local`.
- A stale `MQTT_URL` row in the database combined with an environment password binds the password to the stored broker, not the one in the environment.
- An invalid `POLICY_RULES` file is only logged once at the import and not retried.
- No step-up for backup/audit retention and `DEVICE_NETWORKS` widening (product principle: routine settings do not ask).
- The marker rows (`_env_import` and similar) are protected only as ordinary database rows.
- MQTT brokers on `ws://` / `wss://` are refused, not filtered (paho cannot take the address filter for websockets); `tcp://` and `ssl://` only (S18).
