# Firmware page security notes (cache management, prefetch, changelog)

Code: `internal/firmware/{notes,manage,fleet,prefetch}.go`, `internal/web/firmware*.go`, `internal/app/firmware_inuse.go`. Design: spec §8.2a.

| ID  | Rule | Test |
| --- | ---- | ---- |
| F1  | Release notes are third-party text. `ParseNotes` returns plain data (blocks, inlines); the template prints every string through `html/template`. There is no `template.HTML`, no raw-HTML pass-through, no image loading. Raw HTML, `<script>`, event handlers and attribute breakouts appear as escaped text. The strict CSP (`script-src 'self'`) stays; this is the first line, not the only one. | `TestFirmwarePageEscapesHostileReleaseNotes`, `TestParseNotesKeepsHTMLAsText`, `FuzzParseNotes` |
| F2  | A link in notes is rendered only if `NoteLink` accepts it: `SafeLink` (absolute `http`/`https`, non-empty multi-label DNS host, no user info, no whitespace, control or format characters (Cc, Cf) or backslash, at most 2048 bytes, only the default port) and the host is on the allow-list (`firmware.DefaultNoteLinkHosts`: github.com, *.github.com, tasmota.github.io, tasmota.com, *.tasmota.com; `web.Deps.NoteLinkHosts` overrides). IP literals in any spelling, `localhost`, single-label names, `.local`/`.internal`/`.lan`/`.home` and similar suffixes are refused, so a link can never point into the reader's LAN (a Tasmota without web password runs GET commands). Refused links render as their label text, with balanced parentheses so no leftovers remain. `javascript:`, `data:`, `file:`, `vbscript:`, relative and protocol-relative URLs are dropped (the words stay). Every external anchor has `rel="noopener noreferrer nofollow"`. The release page URL from the index goes through the same gate. | `TestSafeLinkAcceptsOnlyAbsoluteHTTP`, `TestParseNotesDropsUnsafeLinks`, fuzz invariant |
| F3  | Input is bounded: a body is cut to 32 KiB on a rune boundary when the index is read, at most 1500 lines of 4000 bytes are parsed. Parsing is not linear: an unterminated `[`, `` ` `` or `http://` rescans the rest of its paragraph, so the worst case is quadratic in the (capped) paragraph, measured about 6 ms per body, up to about 60 ms per page view for ten releases. | `TestParseNotesBoundsInput`, `TestReleasesCarryNotesFromTheGitHubIndex` |
| F4  | Deleting cached files is admin only, needs a confirmation page (`confirm=yes`), and is audited with release, file, SHA-256 and size; refusals, files kept by the bulk "Delete N unused…" and concurrent deletes (not found) are audited too. The bulk "Delete N unused…" deletes only the ids on the confirmed list, each re-checked by the cache. | `TestFirmwareDeleteNeedsAdminConfirmationAndIsAudited`, `TestFirmwareDeleteSelected`, `TestDirectESP8266JobRecordsTheMinimalArtifact` |
| F5  | A file referenced by an active or queued job, as target or as tasmota-minimal (recorded in the job row for direct ESP8266 plans too, since Tasmota's own fallback may fetch it), is never deleted; the refusal names the jobs. If the in-use lookup fails, nothing is deleted (fail closed), also by the bulk "Delete N unused…". The page shows no delete link for such a file, and the server enforces it independently of the page. | `TestDeleteRefusedWhileInUseNamesTheJobs`, `TestDeleteFailsClosedWhenInUseLookupFails`, `TestDeleteUnusedKeepsWhatJobsNeed`, `TestFirmwareDeleteRefusedWhileInUse`, `TestJobsByArtifactCoversTargetAndMinimal`, e2e `firmware-page` |
| F6  | Prefetch takes only a release name from the form and only if the index lists it; the file list comes from the inventory (`FleetNeeds`). Every file goes through `Cache.Ensure`: allowlisted hosts, size limit, cross-check, image-header check are unchanged. One run at a time, 30 minute timeout, audited. | `TestFirmwarePrefetchFetchesExactlyTheFleetFiles`, `TestPrefetchKeepsCrossCheckAndContinuesAfterAFailure`, `TestPrefetchAllowsOneActiveRun` |
| F7  | The page names devices (id, name) only; no address, credential or note leaves the inventory through it. | page tests |

Residual: `Job.TargetArtifact`/`MinimalArtifact` are written when planning finishes (`EvPlanned`), and planning can include a download of the target and minimal image (seconds to minutes). During that window the job holds no artifact id, so `Delete` accepts the file. This is acceptable because it fails safe: `stageArtifact` re-ensures the file, gets a different id and refuses (`artifact ... is #Y, planned #X`), so wrong firmware is never flashed; the job fails, availability only, and only an admin can trigger it. A second admin browser tab can show a stale "no delete link" state; the server decides. The prefetch stream re-checks the session and the admin role every `SSERecheck`.
